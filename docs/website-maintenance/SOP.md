# 官网人工维护 SOP

## 1. 收集资料

每项更新至少记录正式名称、起止日期、地点、状态、简介、公开数据、图片、版权/授权、多语言范围和明确不展示的信息。不得只凭文件名判断图片归属。

## 2. 判断变更类型

- 内容/元素：活动、文章、统计数字、图片、合作伙伴、局部卡片或样式，可按正常流程修改。
- 架构：数据模型、目录、路由、共享组件、依赖、构建、部署、全局策略。人工维护者先发起讨论；AI 工具必须取得两次明确确认。

## 3. 更新权威数据源

1. 活动事实写入 `activity-catalog.ts`，多语言文案写入 `activities.ts`。
2. 合作伙伴素材状态写入 `partner-catalog.ts`，多语言文案写入 `partners.ts`。
3. 全站数字只改 `stats.ts`。
4. 文章只改 Markdown 源文件。
5. 图片按稳定 ID 建目录，头图放第一位。

## 4. 自检

- 日期与状态一致，活动排序正确。
- 全站同一数字一致。
- 品牌名、定位、时态符合规则。
- 图片存在、归属正确、具有授权。
- 缺少 Logo 的伙伴仍标记为待补。
- 未发生事项没有写成事实。

## 5. 自动检查与预览

依次运行：`npm run validate:content`、`npm test`、`npm run build`。界面变更再检查桌面、手机、键盘、减少动画、二维码和横向溢出。更新本地预览、单文件候选上线版、修改记录及待补资料清单。

## 6. 审阅与发布

第一轮确认内容和视觉；校正后再次构建。准备上线时展示最终差异、检查结果、仓库和分支，取得第二次推送确认。没有双重确认时只保留本地文件。
